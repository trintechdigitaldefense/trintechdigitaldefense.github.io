// deployment

Single-sensor pilot recommended: one always-on Linux host (Termux acceptable for light pilots). Run setup, doctor, continuous protection. Weekly: doctor, PDF, review alerts. See GitHub README for CLI.

// operational approach

The goal is to move from a successfully tested codebase toward a consistently reliable operational security tool. Sentinel’s initial three-day setup establishes a working baseline; it is the beginning of an ongoing operational process, not a claim of production certification.

  1. Day 1 — Establish the baseline

    Confirm installation health, permissions, canaries, monitoring and alert logging. Record what Sentinel considers normal.

  2. Day 2 — Operate and observe

    Run monitoring cycles, examine alerts, distinguish expected activity from suspicious activity and correct false positives.

  3. Day 3 — Operational readiness review

    Review detection results, service stability, reporting, recovery procedures and outstanding limitations.

  4. After Day 3 — Continuous improvement

    Operate within the supported capabilities of the current environment. Review findings, improve detections and strengthen controls as evidence becomes available.
