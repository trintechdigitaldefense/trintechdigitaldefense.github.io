02 // Security reporting

Responsible disclosure

To report a suspected vulnerability in a TrinTech-owned website or service, contact trintechdigitaldefense@gmail.com. Share only the minimum information needed to describe the issue. Do not include passwords, access tokens, personal records, or data belonging to other people.

Do not test, scan, access, or disrupt any system unless you have explicit written authorisation and an agreed scope. Sending a report does not grant permission to test.

Draft · not yet approved

The proposed Responsible Disclosure Policy draft identifies decisions that management and legal counsel must approve before a formal policy can be published. It does not promise response times, safe harbour, or a defined in-scope asset list.

03 // Client information

Client enquiries and confidentiality

The service enquiry page prepares a message in the visitor's own email application. The static website does not receive or store enquiry form fields. Email and WhatsApp providers process messages under their own terms and privacy practices.

  • Share only a high-level description in the first enquiry.
  • Never send passwords, private keys, access tokens, raw logs, vulnerability evidence or personal records through the public enquiry route.
  • Agree written scope and authorisation before assessment work begins.
  • Use an agreed secure channel for sensitive evidence and reports.

There is no public client portal or customer login on this GitHub Pages site. See the client portal architecture note for the separate, not-yet-deployed design.

04 // Hosting transparency

Website security configuration

This site is published through GitHub Pages. GitHub Pages does not apply a repository .headers file as HTTP response-header configuration. A CDN or other edge host must be configured separately for headers such as Content-Security-Policy, Referrer-Policy and Strict-Transport-Security.

Current verification status: effective response headers and browser-side production behaviour have not been independently verified in this review. See the hosting security-header deployment notes.
